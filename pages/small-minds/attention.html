Small Minds · Part 5

Paying Attention in One Pass

How isolated token vectors learn to talk to each other: Queries, Keys, Values, RoPE clockwork, FlashAttention's single-pass trick, and the modern RMSNorm + SwiGLU block.

Scroll down to read ↓

Consider two English sentences containing the exact same word:

"She sat beside the mossy river bank."
"She walked into the downtown bank."

Right after the embedding table in Part 4, both occurrences of "bank" pull the exact same row from W_E. That static vector has no idea whether water or money is sitting three words earlier. Worse, look at the sentence marching across the hero overhead: "The small cat saw a star and chased its warm glow." On its own, the pronoun "its" is an empty placeholder — to know what "its" means (and predict "warm glow" instead of "tail"), position 8 has to reach backward across the sentence and pull context from "star" and "cat"!

In 2017, a team of researchers published Attention Is All You Need, introducing the Transformer — an architecture whose central mechanism lets every token dynamically search all earlier tokens and blend their information using nothing more than dot products (Part 2) and softmax (Part 1). Every modern LLM ever since — GPT, Claude, Gemini, Llama, Qwen, DeepSeek, and the WebGPU model running on this site — is a stack of Transformer blocks.

Click next head in the hero above to watch four parallel attention heads inspect the same sentence with four different jobs: Head 0 tracks the subject ("cat"), Head 1 hugs neighboring syntax, Head 2 links long-range pronouns ("its" → "cat", "glow" → "star"), and Head 3 averages broad tone. Notice that bright ribbons only ever arc backward to the left: because this model predicts the next token, position t is strictly forbidden from peeking into the future (t+1, t+2, …).

Step 1 · Searching contextQueries, Keys, and Values

How do you let every token ask a question of every earlier token using only matrix math? Imagine walking into a quiet library where every earlier token is a book sitting on a shelf. Three separate roles make a search work:

  • Query (Q) — "What am I looking for?" The current token ("its") writes down a search request vector, something like "looking for a singular noun that came earlier!"
  • Key (K) — "What label is on my spine?" Every earlier token advertises a short index card describing what kind of information it holds ("I am a noun: star!", "I am a verb: chased!").
  • Value (V) — "What notes should I hand over if you pick me?" If a book's Key matches the Query, it hands over its Value vector — the actual semantic payload to blend into the current token's representation!

How does one token vector x (say, 64 numbers long) produce three different vectors q, k, and v? By multiplying it by three learned weight matrices — W_Q, W_K, and W_V! Remember Part 2: each matrix just projects the same token arrow through a different geometric lens.

Now wire up the entire scaled dot-product self-attention recipe in four lines that use only tools from Parts 1 and 2: 

// 1. Project every token into Query, Key, and Value grids (using Part 4's tiled matmul):
Q = X · W_Qᵀ      K = X · W_Kᵀ      V = X · W_Vᵀ

// 2. Score every (query i, key j) pair with a dot product, scaled by 1/√d_h:
score[i, j] = (Q[i] · K[j]) / √d_h           // dot product = alignment!

// 3. Causal mask (no peeking ahead!) + Softmax across valid past keys j ≤ i:
if (j > i) score[i, j] = −∞                  // exp(−∞) = 0% attention on future tokens
weight[i, 0..i] = softmax(score[i, 0..i])    // probabilities summing to 100%!

// 4. Weighted average of earlier Value vectors:
out[i] = Σ (weight[i, j] · V[j])             // blend the matching books' notes!

Pause on two tiny details that trip up almost every newcomer until someone spells them out:

  • Why divide by √d_h? Suppose each query and key has d_h = 64 random numbers around size ±1. When you multiply 64 pairs and add them up, a random walk of 64 terms has typical spread around √64 = 8 (so scores swing between −16 and +16). Feed +16 into softmax and e16 ≈ 8,886,110 — one single lucky token grabs 99.9999% of the weight, every other token gets 0%, and the softmax curve goes totally flat so gradients die! Dividing by √d_h keeps the typical score spread right around ±1 regardless of head width, so softmax stays smooth and trainable.
  • Why multiple heads (Multi-Head Attention)? A single attention score has to blend everything into one average. Instead of using one giant 64D head, the model slices the 64D vector into H = 4 parallel heads of d_h = 16 dimensions each! Head 0 can focus exclusively on finding the subject, Head 1 can copy the previous character, Head 2 can track open quotation marks, and Head 3 can watch rhyming syllables — all at the exact same time. Afterwards, the 4 heads' outputs concatenate back into a 64D vector and pass through an output mixing matrix W_O.

Step 2 · Position as angleRotary Positional Embeddings (RoPE)

Look back at the attention equation Q[i] · K[j] and notice a sneaky problem: dot products are completely blind to word order! Take the two sentences "dog bites man" and "man bites dog." Aside from the causal mask, every token vector is identical — attention is a "bag of words" that cannot tell whether "cat" appeared 2 tokens ago or 200 tokens ago!

The original 2017 Transformer patched this by adding a fixed sine/cosine vector directly onto each token's embedding at the entrance of the network. That worked, yet it tangled "what a word means" together with "its absolute page number" — if a model trained on 512-token essays ever met token #600, it had never seen position 600 before.

In 2021, Jianlin Su and collaborators introduced a breathtakingly cleaner geometric idea now used by nearly every modern open-weight LLM (Llama, Qwen, DeepSeek, Mistral, and Small Minds): Rotary Positional Embeddings (RoPE).

Instead of adding a position stamp to a token, RoPE rotates its Query and Key vectors like hands on a wall of clocks! Take a head's coordinates and group adjacent entries into 2D pairs: (x₀, x₁), (x₂, x₃), (x₄, x₅), … Each pair is a tiny 2D arrow on a circle (just like Part 2!). For a token sitting at position t, rotate pair p counterclockwise by an angle proportional to t: 

// Frequency of clock p: fast second-hand for pair 0, slow hour-hand for later pairs
ω_p     = θ^(−2p / d_h)                       // θ is typically 10,000 (or 1,000 for short ctx)
angle   = t · ω_p

// Exact 2D rotation matrix from high-school trigonometry (rope_apply in ops.wgsl):
x₀_rot  = x₀ · cos(angle) − x₁ · sin(angle)
x₁_rot  = x₀ · sin(angle) + x₁ · cos(angle)

Why is rotation pure magic? Suppose Query sits at position m (rotated by m · ω) and Key sits at position n (rotated by n · ω). Remember Part 2's dot-product identity: the dot product of two 2D arrows depends only on the angle between them! Subtract their two angles: 

(m · ω) − (n · ω)  =  (m − n) · ω      // absolute positions cancel — ONLY relative distance survives!

Whether the phrase "the small cat" sits at positions (5, 6, 7) or at positions (1005, 1006, 1007), the relative angle between "cat" and "small" is mathematically identical! Fast clocks (ω ≈ 1) track crisp neighbor-to-neighbor syntax ("1 word back vs. 2 words back"), while slow clocks (ω ≈ 0.001) barely turn over hundreds of tokens, letting the model measure long-range paragraph distance without wrapping around.

Prove this invariance to yourself live in Figure 1 below. Move query pos m and key pos n upward by the exact same step — for example, shift (12, 5) up to (20, 13), keeping their distance Δ = 7 unchanged. Watch all four clock hands spin around their circles while every green wedge and every cosine score stays frozen to the third decimal place!

Try also dragging RoPE base θ down toward 100 versus up to 10,000: smaller θ spins the slower clocks faster (sharper resolution on short sequences, which is why Part 7's AutoResearcher tests θ = 1000 vs 10000!). And when backpropagation flows backward through RoPE in Part 6, inverting a rotation by angle +α is simply rotating by −α — the exact same WGSL shader rope_apply called with sign = -1.0!

Step 3 · Online softmaxFlashAttention in one pass

You now have causal multi-head attention with RoPE. Write it the naive textbook way, however, and you slam straight into the exact same GPU memory-bandwidth wall from Part 4 — only now it scales quadratically with sequence length T!

Count the VRAM trips of textbook attention on a sequence of length T:

  1. Compute all pairwise scores S = QKᵀ / √d_h and write the entire T × T grid to slow VRAM.
  2. Read that T × T grid back out of VRAM to compute row-wise softmax probabilities P, then write the T × T matrix P back to VRAM.
  3. Read P out of VRAM a third time to multiply by V!

For a tiny 48-token demo, 48 × 48 = 2,304 floats is harmless. At T = 16,384 tokens across 32 attention heads, a single T × T score grid swells to 34 gigabytes of temporary scratch memory per layer — instantly blowing up a GPU before a single answer finishes!

Why did textbook softmax force the GPU to write the whole row to VRAM first? Because safe softmax (remember Part 1's deep dive!) seems to require two passes over all keys: Pass 1 to find the row's maximum score m and denominator sum l = Σ exp(s_j − m), and Pass 2 to divide every weight by l and blend V.

In 2022, Tri Dao and colleagues realized you can compute exact softmax and the weighted average of V in one single streaming pass — never allocating or writing the T × T matrix to VRAM at all! That algorithm is FlashAttention, and its mathematical trick (online safe softmax) is shockingly simple once you trace three numbers by hand.

Suppose scores arrive one by one: first s₀ = 1.0, then s₁ = 3.0, then s₂ = 2.0. Keep just three tiny numbers in ultra-fast GPU registers: the largest score seen so far m, the running exponential sum l, and the running weighted output O: 

// Key 0 arrives with score s₀ = 1.0 (value V₀):
m = 1.0,   l = exp(1.0 − 1.0) = 1.0,   O = 1.0 · V₀

// Key 1 arrives with a BIGGER score s₁ = 3.0! Oops — the old max was too small!
// Fix every past term in ONE multiply: rescale old l and old O by α = exp(m_old − m_new):
m_new = 3.0,   α = exp(1.0 − 3.0) = exp(−2.0) ≈ 0.1353
l = 1.0 · exp(−2.0) + exp(3.0 − 3.0) = 1.1353
O = O   · exp(−2.0) + 1.0 · V₁       = exp(−2)·V₀ + 1.0·V₁   // EXACTLY as if max=3 was known from start!

// Key 2 arrives with s₂ = 2.0 (smaller than m=3.0, so α = exp(3−3) = 1):
l = 1.1353 + exp(2.0 − 3.0) = 1.5032
O = O      + exp(−1.0) · V₂

// End of row: divide O by l once!
final_out = O / l

Check the algebra on O: multiplying the earlier exp(1 − 1) by exp(1 − 3) gives exp(1 − 1 + 1 − 3) = exp(1 − 3)! The old maximum cancels out identically, leaving the exact mathematical output of two-pass softmax with zero approximation! Here is the entire inner loop inside attention.wgsl: 

let m_new = max(m_i, score);
let alpha = exp(m_i - m_new);
let p_ij  = exp(score - m_new);
oAcc = oAcc * alpha + p_ij * V[kt];
l_i  = l_i * alpha + p_ij;
m_i  = m_new;

Step 4 · Modern blockThe residual highway, RMSNorm, and SwiGLU

Attention lets tokens gather context from their neighbors, yet attention alone is only half of a Transformer layer. Once token "its" has gathered information from "star", it needs a private workbench to digest what it learned, recall memorized patterns ("stars glow warmly in haiku!"), and update its meaning vector. That workbench is the Feed-Forward Network (FFN) — a miniature two-layer MLP (just like Part 2!) applied independently to each token vector.

Here is the complete wiring diagram of one modern Transformer block (used in Llama 3, Qwen, DeepSeek, and Small Minds): 

                  ┌──────────────────────────────────────────┐
                  │         (residual skip connection)       │
input stream x ───┴─▶ RMSNorm ─▶ Multi-Head FlashAttn (+RoPE) ─▶ (+) ──▶ x_mid
                                                                           │
                  ┌──────────────────────────────────────────┐             │
                  │         (residual skip connection)       │             │
x_mid ────────────┴─▶ RMSNorm ─▶ SwiGLU Feed-Forward Net ──────▶ (+) ──▶ x_out

Three quiet engineering breakthroughs hold that diagram together — and explain why modern models train so much more cleanly than the original 2017 design:

  1. The Residual Stream (x + sublayer(x)): Notice that neither attention nor the FFN replaces the token vector x — they both add a small refinement back onto x! Think of x as a conveyor belt rolling straight from the embedding table at layer 0 all the way to the final vocabulary head. Layer 1 reads from the belt and writes a note onto it; Layer 2 reads both the original token and Layer 1's note and adds another refinement. And as Part 6 will prove, that addition highway also lets gradients cruise smoothly backward through dozens of layers without dying.
  2. Pre-Norm with RMSNorm: If you keep adding vectors layer after layer, some token vectors drift up to length 500 while others shrink to 0.01, making dot products and bends go haywire. Before each sub-block, RMSNorm (Root Mean Square Normalization) measures the vector's root-mean-square size rms = √(mean(x²) + ε), divides every entry by rms to lock the vector's scale back to 1.0, and multiplies by a learned per-dimension gain γ. Compared to 2017's LayerNorm, RMSNorm skips subtracting the mean, cutting memory reads in half with identical accuracy.
  3. SwiGLU Gated Feed-Forward Network: A classic FFN runs one linear layer up to a wider workspace, applies ReLU/GELU, and projects back down. SwiGLU (introduced by Noam Shazeer in 2020) splits the upward projection into two parallel paths: a gate passed through smooth SiLU(g) = g · σ(g), and an up signal, then multiplies them element-by-element before projecting back down: 
    SwiGLU(x) = W_down · ( SiLU(W_gate · x) ⊙ (W_up · x) )
    Multiplying by a smooth gate gives every hidden feature its own continuous dimmer switch — passing useful memories through cleanly while silencing irrelevant ones without sharp kinks.

Step 5 · Zooming outStacking blocks: from 100K to 100 Billion

Stack L copies of that exact block one after another, apply one final RMSNorm, and multiply by the final output matrix W_LM ([vocabSize, dModel]) to turn each token's D-dimensional final thought into V raw logits — right back to Part 1's softmax!

Here is the wild truth about modern AI: the browser model running on this page and a frontier 70-billion-parameter model have the exact same blueprint — literally the same RMSNorm, RoPE, multi-head causal FlashAttention, SwiGLU FFN, and residual stream. The only difference is how wide and tall the rectangles are! Count every weight inside one block using the exact formula from checkpoint.ts:
